## 访谈原则

把访谈当成共同备课，而不是填写表单。

- 先读取用户提供的资料和工作区内容，再问无法发现的偏好。
- 每轮询问 2–4 个问题，先问会改变作品结构的事项。
- 给出有意义的选项和推荐理由；不要提供明显无效的选项。
- 根据回答追问矛盾、过宽范围、缺失资料和不可验证结论。
- 不重复询问已知信息，不为了“多问”而制造负担。
- 未获得创作简报确认前，不写成品文件、不调用生图、不打包。

Codex 支持结构化用户输入时优先使用；否则使用简短编号问题并等待回答。

## 必须锁定的信息

| 维度 | 必须得到的答案 | 影响 |
|---|---|---|
| 学习目标 | 用户完成后应理解、判断或完成什么 | 内容取舍与验收 |
| 受众 | 年龄/角色、已有知识、语言 | 术语、节奏和解释深度 |
| 范围 | 必讲、可略、不要涉及的内容 | 作品边界 |
| 深度 | 入门、核心机制、深度推导或实战 | 章节和信息密度 |
| 作品形态 | 交互演示、动态书、合集 | 布局和打包 |
| 知识结构 | 时间、因果、层级、比较、空间或系统关系 | 叙事与图形编码 |
| 交互 | 用户操作、可观察变化、反馈与重置 | 状态模型 |
| 视觉 | 知见默认、具体方向、禁用风格 | 创意表达层 |
| 素材数据 | 用户素材、可信来源、是否允许示意数据 | 准确性和资源 |
| 约束 | 设备、时长、无障碍、离线/CDN | 技术方案 |
| 封面 | 图片或 HTML、风格、是否需要文字 | 封面工作流 |
| 合集结构 | 学习路径、作品边界、章节层级、作品顺序 | `collection.json` 与整包交付 |
| 合集资料 | 短简介、完整介绍、合集级封面 | 合集卡片与详情页 |

## 推荐轮次

### 第一轮：教学意图

优先询问：

1. 学习者完成作品后最重要的收获是什么？
2. 受众是谁，他们已经知道什么？
3. 哪些内容必须包含，哪些内容应避免？

### 第二轮：作品机制

根据第一轮给出推荐，再确认：

1. 使用交互演示、动态书还是合集？
2. 希望用户通过什么操作发现什么变化？
3. 是否有必须使用的数据、公式、图片或资料？

选择合集时继续确认：各子作品是否能独立理解、章节最多需要几层、作品是否有强制顺序，以及合集级介绍和封面如何区别于单作品资料。

### 第三轮：表达与交付

仅询问仍缺失的事项：

1. 视觉方向和需要保留/避免的风格是什么？
2. 主要设备、时长、无障碍或离线要求是什么？
3. 使用 ImageGen 图片封面还是确定性的 HTML 封面？是否在图中写标题？

主题很简单且用户已给出完整信息时可以合并轮次；主题宽泛、存在争议或适合合集时继续追问。

## 创作简报模板

```markdown
## 创作简报

- 主题：
- 学习目标：
- 目标受众与已有基础：
- 内容范围与深度：
- 必须准确表达的结论：
- 作品结构：单作品 / 合集；交互演示 / 动态书
- 合集学习路径与章节树：
- 子作品清单：目录键；标题；类型；学习目标；核心交互
- 内容模块：
- 核心交互与反馈：
- 视觉方向：
- 素材与数据来源：
- 封面：图片 / HTML；风格；是否含文字
- 合集封面与各作品封面：
- 技术与无障碍约束：
- 验收标准：
- 采用的默认值：
- 风险或待补资料：
```

展示简报后明确请求确认。用户修改任一关键项后，更新简报并重新确认。

## 默认值

用户授权采用默认值时使用并明确列出：

- 受众：对主题感兴趣但没有专业背景的中文用户
- 深度：解释核心机制，并提供一个可操作示例
- 作品形态：能在一个视口内讲清则用交互演示，否则用动态书
- 视觉：知见品牌基础 + 与主题匹配的克制创意表达
- 设备：桌面优先，兼容 390px 宽手机
- 无障碍：键盘可用、可见焦点、足够对比度、支持减少动画
- 封面：先推荐；概念/情绪型主题优先图片，结构/数据/标题型主题优先 HTML
- 图片文字：默认不在图片内重复标题

## 场景判断

- **适合交互演示**：参数变化、动态过程、数据比较、空间关系、模拟实验。
- **适合动态书**：多章节解释、长篇教程、证据链、逐步推导、多个内嵌演示。
- **适合合集**：子主题能独立学习、存在明确先后关系、单个作品会过密。
- **需要资料**：结论依赖实时数据、专业标准、精确历史事实或用户私有内容。
- **不应强行交互**：操作不会改变理解，只是播放装饰动画或切换重复文本。
